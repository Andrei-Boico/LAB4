### Ответы на контрольные вопросы:
- Какой ключ у картинки?  
  uploads/<имя_файла_картинки> (например, uploads/image.png). В Amazon S3 ключ (Key) — это полный уникальный путь к объекту внутри бакета от самого корня.
- Почему Object URL не открывается, хотя вы владелец бакета?  
  Параметр Block All Public Access и отключённые списки доступа (ACL) строго блокируют анонимные публичные HTTP-запросы. Переход по Object URL в браузере выполняет неавторизованный GET-запрос без передачи ключей доступа AWS, поэтому S3 отклоняет его с ошибкой AccessDenied.
- Что на самом деле создала кнопка Create folder?  
  В Amazon S3 нет реальной файловой системы с папками. Кнопка Create folder создаёт системный объект нулевого размера (0 Bytes), имя ключа которого оканчивается на слэш (uploads/). Консоль AWS интерпретирует такие объекты как виртуальные директории.

2. В CloudShell проверена работа политики:

     aws s3 ls s3://$BUCKET/uploads/
   - Запрос по HTTP принудительно заблокирован:  
     aws s3 ls s3://$BUCKET/uploads/ --endpoint-url http://s3.eu-central-1.amazonaws.com  
     (Получена ошибка AccessDenied).

### Ответы на контрольные вопросы:
- Почему вторая команда получает AccessDenied, хотя у вас права администратора?  
  В системе IAM явный запрет (Deny) обладает абсолютным приоритетом над любыми разрешениями (Allow). Так как запрос через endpoint http://... шёл по незащищённому HTTP, сработало условие "aws:SecureTransport": "false", и правило Deny заблокировало доступ.
- Почему Block Public Access не помешал сохранить политику с "Principal": "*"?  
  Защита Block Public Access блокирует только политики, содержащие разрешающие правила (Allow) для публичного доступа. Настоящая политика содержит только явный запрет (Deny) незащищённых подключений, что не делает бакет публично доступным.

5. Проведено окончательное (перманентное) удаление конкретной версии v2, в результате чего текущей (активной) версией автоматически стала v1.

### Ответы на контрольные вопросы:
- Чем удаление в шаге 3 отличается от удаления в шаге 5?  
  В шаге 3 создаётся Delete marker (маркер удаления), а сам файл и его предыдущие версии физически остаются сохранёнными в хранилище. В шаге 5 происходит окончательное физическое удаление (Permanent delete) конкретной версии объекта без возможности её восстановления.
- Какое из них можно отменить?  
  Отменить можно только удаление через Маркер (шаг 3), удалив сам маркер удаления. Перманентное удаление конкретной версии (шаг 5) отменить невозможно.
- Какой из двух способов защищает от случайного удаления, а какой нужно запрещать приложению?  
  Маркеры удаления защищают от случайной утраты данных. Приложению (и его IAM-роли) следует строго запрещать право s3:DeleteObjectVersion (перманентное физическое удаление), разрешая при необходимости только s3:DeleteObject.

## Задание 5. Правило жизненного цикла

### Выполненные действия:
В разделе Management -> Lifecycle rules создано и активировано правило timecapsule-dev-noncurrent со следующими параметрами:
- Область действия: Фильтр по префиксу uploads/
- Переход неактуальных версий: В класс Standard-IA через 30 дней.
- Удаление неактуальных версий: Окончательное удаление через 90 дней, сохраняя 2 самые новые неактуальные версии (Number of newer versions to retain: 2).
- Удаление незавершённых загрузок: Очистка незавершённых составных загрузок (incomplete multipart uploads) через 7 дней.

### Ответы на контрольные вопросы:
- Как поведёт себя правило для файла, который перезаписывали 10 раз за неделю? Какие версии и когда окажутся в Standard-IA, какие будут удалены?  
  У файла появится 1 текущая и 9 неактуальных версий. Через 30 дней 7 самых старых неактуальных версий перейдут в Standard-IA (так как 2 наиболее свежие неактуальные версии остаются в Standard). Через 90 дней эти 7 старых версий будут окончательно удалены.
- Почему наши маленькие тестовые файлы в Standard-IA не попадут?  
  Класс хранения S3 Standard-IA имеет минимальный учитываемый и тарифицируемый размер объекта 128 КБ. Объекты меньшего размера игнорируются при переносе.
- Что такое незавершённая загрузка частями и почему за неё приходится платить?  
  При загрузке крупных файлов частями (Multipart Upload) файл разбивается на блоки. Если процесс прерывается из-за сбоя сети или ошибки скрипта, загруженные блоки остаются на серверах AWS. Они занимают дисковое пространство и тарифицируются по стандартной стоимости хранения до тех пор, пока их не зачистит правило Lifecycle.

### Ответы на контрольные вопросы:
- Какие ошибки вернул S3 в шагах 3 и 4?  
  В шаге 3: SignatureDoesNotMatch. В шаге 4: AccessDenied (Request has expired).
- Почему нельзя получить другой файл, просто поменяв ключ в ссылке?  
  Подпись URL рассчитывается криптографическим алгоритмом HMAC с использованием ключей AWS и включает в себя конкретный ключ объекта (path). Любое изменение пути ломает валидность HMAC-подписи.
- Обращалась ли команда aws s3 presign к S3, когда создавала ссылку?  
  Нет, не обращалась. Команда выполняет расчёт HMAC-подписи исключительно локально на клиенте, используя текущие ключи доступа AWS (AWS Credentials), имя бакета и временную метку.
